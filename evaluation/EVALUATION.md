## OBJECTIVE

This document explains how to run the evaluation code, the supported evaluation modes, how input data must be structured, and how configuration (model and embeddings) is handled.


## GENERAL COMMAND FORMAT

The evaluator is executed from the command line using the following pattern:

```python 
python <evaluator_file_name>.py --dataset <path_to_dataset>
```

Where:

<evaluator_file_name>.py is the Python file that contains the evaluation logic.

<path_to_dataset> is the path to a JSON file containing test cases.

## EVALUATION MODES

There are three supported evaluation modes. Each mode exists because RAGAS datasets only support a fixed set of fields.

### RAG MODE

**Metrics** included:

- Context Precision (built-in)

- Context Recall (built-in)

**Purpose:**

Evaluate retrieval quality only.

No LLM answer generation is required.

---

### ANSWER MODE

**Metrics** included:

- Faithfulness (built-in)

- Answer Relevance (built-in)

- Answer Accuracy (custom)

**Purpose:**

Evaluate the quality and correctness of the final answer.

Measures whether the answer is relevant, factually grounded, and accurate with respect to the ground truth.

*Notes on Answer Accuracy:*

Produces a continuous score between 0 and 1.

At the return step, the score is thresholded (default 0.8, configurable at initialization).

Final output is **binary**: 1 if score >= threshold, otherwise 0.

---

### REASONING MODE

**Metrics** included:

- Reasoning Recall (custom)

**Purpose:**

- Evaluate whether the model’s reasoning covers the ground-truth reasoning steps.

- Each ground-truth reasoning sentence is evaluated independently.

- Final score is the fraction of ground-truth steps recovered by the model.


## INPUT JSON DATA

RAGAS datasets only support the following four fields internally:

- user_input

- response

- retrieved_context

- reference

Because of this limitation, the attribute name from the json file will be renamed to match the available fields.

### SAMPLE INPUT JSON FORMAT

The following is an example of a raw test case before it is adapted to a specific evaluation mode:
```json
{
    "test_cases": [
        {
        "question": "A 62-year-old man presented with a 4-month history of progressive dysphagia that initially involved solid foods and later progressed to difficulty swallowing liquids. He also reported unintentional weight loss of approximately 8 kg over this period. He denied odynophagia, hematemesis, or prior history of gastroesophageal reflux disease. Physical examination was unremarkable. Laboratory studies showed mild normocytic anemia. Contrast-enhanced CT of the chest demonstrated an irregular, circumferential thickening of the mid-esophagus with luminal narrowing. A barium swallow study showed an irregular narrowing with shouldered edges. There was no evidence of distant metastasis on imaging.",
        "ground_truth": "esophageal malignancy",
        "ground_truth_reasoning": "Progressive dysphagia suggests esophageal malignancy.\nWeight loss supports a malignant process.",
        "contexts": [
        "Esophageal carcinoma commonly presents with progressive dysphagia that advances from solids to liquids and is frequently associated with weight loss.",
        "Benign strictures are usually related to chronic reflux or caustic injury and are less commonly associated with marked weight loss."
        ],
        "answer_reasoning": "Significant weight loss further supports a malignant etiology.",
        "answer": "progressive dysphagia"
        }
    ]
}
```

### FIELD DEFINITIONS

- question:
    + Type: String

    + The user query or clinical case. 

    + Mapped to `user_input` in all modes.

- ground_truth:
    + Type: String

    + The correct final diagnosis.

    + Used as `reference` in Answer mode.

- ground_truth_reasoning:
    + Type: String

    + The standard reasoning.

    + Each reason is separated by a newline character `\n`.

    + Used as `reference` in Reasoning Recall evaluation.

- contexts:
    + Type: List[String]

    + Retrieved passages or documents.

    + Used as `retrieved_context` in all mode.

- answer_reasoning:
    + Type: String

    + The reasoning generated by the model.

    + Each reason is separated by a newline character `\n`.

    + Used as `response` in Reasoning mode.

- answer:
    + Type: String

    + The final diagnosis generated by the model.

    + Used as `response` in Answer mode.

## MODEL AND EMBEDDING CONFIGURATION

The LLM and embedding models are configured in the `.env` file.

The current setup uses **Ollama** as the model host.

If a different model provider is used, the LangChain wrapper may need to be changed accordingly.
